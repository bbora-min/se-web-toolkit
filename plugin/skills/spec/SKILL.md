# /se:spec — 요구사항 → 화면 명세

`$ARGUMENTS`(또는 대화의 요구사항)를 읽고 `docs/spec.md`를 채운다. Figma가 없는 팀에서 **이 문서가 디자인 단계**다.

## 절차
1. 요구사항에서 **명사(데이터)**와 **동사(액션)**를 뽑는다. "잡 목록을 상태별로 보고 실패 잡을 재시도" → 데이터: 잡·상태·파이프라인, 액션: 보기·필터·재시도
2. 화면을 나눈다. 대부분 2–4개: 목록(ListDetail) + 상세(드로어 또는 DetailPage) + (개요 Dashboard) + (등록 FormWizard) + (설정 Settings). `se-ui` 스킬의 패턴 선택표로 패턴을 정한다
3. 화면마다 `docs/spec.md` 블록을 채운다: 라우트 · 답하는 질문 · 데이터(엔드포인트·필드·상태 값) · 1차 분류(탭)/2차 필터 · 표 컬럼(이름·상태·사람·시간·숫자 순) · 주/행/위험 액션 · 3상태 문구(톤 맞춤) · 시그니처에 넣을 숫자
4. **디자인 브리프** 한 단락: 첫 시선, 액센트를 쓸 곳, 밀도, 톤 — `se-design`의 플랜 항목과 같다
5. 사용자에게 보여주고 확인받는다. 확인 후 `/se:page <화면>`으로 넘어간다

## 판단 기준
- 화면이 5개를 넘으면 너무 많다 — 탭이나 드로어로 합친다
- 주 액션은 화면마다 하나. "그리고 ~도 할 수 있다"는 행 액션이나 ⋯ 메뉴
- 백엔드 API가 없으면 스펙의 데이터 정의가 곧 MSW 목이 된다 — 필드·상태 값을 구체적으로
